# AI视频本地画质增强

六段原始视频均为852×480。使用官方Real-ESRGAN模型在本地Apple GPU推理，输出3840×2160、30fps；这是经过超分处理的4K，并非即梦原生4K。没有重新生成场景、购买服务或上传素材。

## 采用的处理

- 从原始视频按时间戳采样30fps，不进行AI补帧。原始文件、音频、90秒剪辑与动作卡点不变。
- 通用模型 `realesr-general-x4v3`，与官方弱降噪权重按0.35/0.65混合；使用FP32推理和40像素反射边界，不进行分块推理。
- 模型4倍输出以Lanczos适配4K，再与同帧原片Lanczos放大结果按35%/65%混合。关闭人脸修复、额外锐化、重绘与额外降噪。
- 已比较FAST中段3秒、火光2秒、飞船2秒的原片放大、通用35%、通用55%及插画35%版本。55%削弱部分水彩纹理；插画模型对不同场景的改善不一致，因此选定通用35%。其余三段也使用35%，并分别检查。
- 改善主要在轮廓、建筑切面和局部边缘，远景细节仍受原始480P限制。模型不会恢复真实缺失的工程细节；原视频已有的形变与运动问题也不会因此消失。

## 转场与来源

转场主体、背景与遮罩均以4K生成；光流分析继续使用540P，位移、修补与羽化映射到4K。原有卡面锚点、逐帧主体轨迹、相机时机和音乐保持不变。合成器根据实际素材和坐标尺寸取样，移除固定除以2的假设。

原始来源、原始尺寸及SHA-256仍保存在素材清单中；增强素材单独保存在 `public/ai-enhanced-4k/`。模型官方下载地址、权重校验值和架构来源记录在 `tools/upscale_vendor/sources.json`；架构仅移除了BasicSR注册装饰器，许可证随代码保留。推理依赖固定在项目内 `.venv-upscale/`，锁定版本见 `tools/upscale-requirements.lock.txt`。

## 重现与切换

在混合宣传片目录运行：

```sh
../工具/.venv/bin/python -m venv .venv-upscale
.venv-upscale/bin/python -m pip install -r tools/upscale-requirements.lock.txt
.venv-upscale/bin/python tools/download_upscale_models.py
.venv-upscale/bin/python tools/enhance_ai.py compare
.venv-upscale/bin/python tools/enhance_ai.py full --4k
../工具/.venv/bin/python tools/import_ai.py --variant enhanced --4k
```

切回常规放大素材：

```sh
../工具/.venv/bin/python tools/import_ai.py --variant original
```

切换会同步重建转场素材；已导出的成片不会自动改变，需重新导出。Apple GPU需要运行环境允许访问Metal，受限环境可能显示CPU；启动时会明确报告实际设备。

## 验证边界

技术检查包括原始文件校验、1170帧增强素材完整解码、帧数、尺寸、代表帧保真、转场端点、遮罩、完整轨迹与声音/时间轴校验。记录见 `记录/画质增强技术核对.json` 等文件。同帧MPS推理重复结果一致。

视觉检查结合原尺寸细节图、代表性转场帧、正常速度及半速播放抽查；机器检查不能证明全部细节都真实或完全没有闪烁。没有高清真值，因此不以锐度分数宣称画质提升百分比。

## 整片4K

三维主渲染、4重抗锯齿、接触阴影、标注画布及转场合成画布均为3840×2160。二维标题在2倍输出比例下重新栅格化；保留1920×1080逻辑坐标，使构图、卡面锚点与动作时机不变。视频不是将1080P成片整体放大。输出H.264 CRF16、AAC 256kbps，90秒、30fps。1080P分享版从4K母版缩小，音轨直接复制。

重新导出：`node tools/render.mjs final`，随后 `../工具/.venv/bin/python tools/assemble.py --reuse`。推理、转场生成和最终导出须依次执行。

三维局部对比：`输出/画质增强/三维1080P与4K局部对比.png`。取相同玩法帧，将旧1080P成片放大与新4K重渲染画面按相同像素范围裁切；此图用于观察可读性，不用于评价AI段。
