# 卡面资源说明

`card-assets.json` 是供前端加载的扁平映射：卡牌 ID → 相对页面根目录的 WebP 路径。

- 科技用 `T1-01` 等 ID，事件用 `E01` 等 ID。
- 奇观按时代选择，例如 `W01-1`、`W01-2`。不得只按奇观 ID 固定用同一时代费用。
- 资源用 `R0-1`、`R0-2` 等 ID：0 为金币、1 为人力、2 为矿物；横线后是面值。
- 牌背包括 `back-resource`、`back-event`、`back-tech-1` 至 `back-tech-5`、`back-final`、`back-wonder-1` 至 `back-wonder-5`。

这些 WebP 图片由仓库根目录的 `卡牌/` 卡面导出，保留完整卡面、原比例与透明通道，最长边不超过 900 像素，WebP 品质 85。`card-assets.metadata.json` 记录当前原图路径、摘要、尺寸及导出大小；网页构建会核对这些原图与记录是否一致。缺少完整卡面的 `T2-06` 使用 `web/assets/T2-06-art.webp` 的现成插画替代图。

## 覆盖与例外

60 张科技中，59 张有完整卡面。`T1-01` 驯火与热加工的原图名称为“科技卡牌设计_画板 1.png”，经目视确认后补入。

`T2-06` 光学与透镜只有透明方形插画，导出为 `T2-06-art`。前端应配合当前规则的名称、费用、科研点与效果形成卡片；不应把方形插画拉长当成完整卡面。全部 14 张事件、27 张奇观时代卡面及 12 张资源卡面都有原图。

## 卡面文字与当前规则

卡面是已有实体设计，规则依据以网页内嵌说明书为准；说明书注明以卡牌为准的地方，以对应正式卡面为准。当前规则引擎和实验参数仍负责已经开局的结算，但若与上述依据有差异，须记录并讨论，不能默认为引擎正确。卡牌详情应同时显示实体卡面和本局实际费用、效果，避免玩家在差异厘清前误读。

已目视确认的差异：

- `T1-07` 算术与几何：复查导出的卡面为 3 金币、2 人力，与当前运行规则一致；此前初检误读为 5 金币，已更正。
- `T5-07`：卡面标题为“巨型一体化压铸技术”，当前运行名称为“超大型一体化压铸技术”。

本次逐一检查素材覆盖，并抽样核对画面，不代表已经逐张审核所有印刷文字。发现印刷卡面与说明书或引擎冲突时，先登记差异，再按团队确认的规则层级处理。
